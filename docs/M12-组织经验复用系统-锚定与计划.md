# M12 组织经验复用系统——产品锚定与实施计划

> 本文把"产品到底解决什么"钉死，并给出与既有实现的对应、真正缺口、以及按面试价值的实施顺序。

## 1. 产品定义（一句话）
一个 **"组织经验复用 + 联网补全 + 对话打磨 + 复盘回写"的闭环系统**：沉淀过去同类事项的经验 → 新任务来时检索历史经验 ⊕ 联网补当下信息 → 与人来回讨论 → 把本次结论归档成新经验。可复用的是**这套循环**（活动/年会/策划/会议复盘/事故 postmortem/现场服务都套得上），非某一领域。

### 直观例子（非模板）
骑行社团长要组织"骑到文昌"：系统汇总历任社长同类活动经验（路线、补给、露营点、风险、踩坑）+ 联网补文昌老街/火箭发射窗口等实时信息 → 团长追问细化 → 讨论完把本次方案与学到的经验归档。

## 2. 与已实现能力的对应（锚定，非返工）
| 愿景需要 | 已有 |
|---|---|
| 检索以往经验 | M9b 双库记忆 + M2/M5 混合检索 |
| 当下事实(文昌老街/火箭窗口) | M9a+MiMo 联网、多源佐证 |
| 汇总前任经验成方案 | M9c 研究编排(提纲→逐节→成文带引用) |
| 深入询问来回打磨 | M9c 会话态/refine + M8 self-RAG |
| 讨论完归档有用信息 | P2 `/research/{sid}/publish`(论断→knowledge 记忆) |
| 错误经验不污染后人 | P0 trust 门控(draft 不参与作答、需佐证/促升) |
| 分团队各用各的 | ⑥ 多租户数据面 |

## 3. 真正缺口（不补就是"能讲不能用"）
1. **经验分层可复用**（P3-A，先做）：memory 只有扁平事实句；跨场景迁移靠**两层并存**——`fact`(具体:露营点/发射窗口) + `playbook`(抽象打法:重大活动必做风险预案) + **结构化标签**(type/location/season/difficulty)做精确召回。**这是"可复用"成立的关键，也是可评测的差异化点。**
2. **复盘整体归档**（P3-B）：需要一个 `Event/Playbook` 实体，把一次对话的方案/决策/踩坑/来源/结果归成**整份可检索可引用的经验档案**，而非零散 facts。
3. **结果回标治理**（P3-C，可后置）：经验的可信度最终由**用过之后成没成**驱动（P0 已证"多源一致≠真相"）；需 outcome 反馈字段促升/降权，否则经验随时间腐化。

## 4. 面试/简历定位
- 主叙事 = **面向组织复用的经验记忆 + 联网补全 + 对话式规划闭环**；骑行/年会只作直观例子。
- 差异化：经验分层 + 复盘回写 + 可信度治理，正对"证明已有卖点真实性 > 堆功能"的 AI 后端评价标准；且避开"知识库问答"红海。
- 顺序按面试价值定：**P3-A 先做**（能拿"分层+标签检索 vs 扁平"的消融数据证明可复用，是非显然洞察）；P3-B 是数据建模；P3-C 留增强。

## 5. 实施计划（决策完整）
### P3-A 经验分层可复用
- schema：`memories` 幂等加 `level`(fact|playbook, default fact)、`tags JSONB default {}`；索引。
- store：`add_memory` 带 level/tags；`search_memories` 支持标签过滤(`tags @> :tf`)与 level 过滤、按 level 分域去重；`find_similar` 同 level。
- extract：抽取提示升级，每条事实产出 `{content, scope, level, tags, kind}`；parse_facts 兼容新字段(缺省 fact)。
- publish：claims_to_facts 按节意图打 level(原则/风险→playbook) + tags(取 doc.topic/来源)。
- _memory_context：召回时按 level 分块呈现("经验原则"/"具体事实")，标签命中优先。
- 评测：`scripts/eval_experience_reuse.py`——合成跨场景历史经验集，对比"分层+标签召回 vs 扁平语义召回"在"新任务能否命中可迁移 playbook"上的命中率差，出带 CI 的数（诚实小样本、看趋势）。
- 测试：parse_facts(level/tags)、decide_op level 感知、claims_to_facts level/tags 映射（hermetic）；标签过滤为集成测。

### P3-B 复盘整体归档
- 新增 `events` 表(id/名称/type/时间/tags/summary) + memories.event_id 关联；`/research/{sid}/publish` 接受 event 归属；`get_event_playbook(event_id)` 取整份经验；检索可按 event。
- 测试：事件归档与整份召回。

### P3-C（后）结果回标：feedback 字段 + 按结果促升/降权。

## 6. 交付纪律
每步：代码 + hermetic 单测(+必要集成) + 文档 + 提交推 CI；完成即完成，不拿半截数冒充。服务器运行态每里程碑同步重启。
